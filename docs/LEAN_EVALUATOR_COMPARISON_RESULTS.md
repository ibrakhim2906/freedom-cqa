# Lean versus current: frozen manual comparison

The first lean candidate **fails its promotion gate**. It passes strict validation
on **1/6** first submissions; the current evaluator passes **3/6**. Both engines,
all inputs and the prospective expectations stayed frozen. No repairs were made.
The current runtime default is unchanged.

Implementation: [lean evaluator](LEAN_EVALUATOR.md). Machine-readable evidence:
[comparison audit](../audits/lean-ab-v1-results.json).

## Design

Six new conversations cover RU/KZ/EN twice each, three chats and three calls.
Two use exact supplied official platform references with explicit matching dates
and scope. Four use transparently fictional procedures and event records.
The existing reviewed-015 checklist is unchanged. Both arms receive identical
complete input after removing only their output-contract discriminator.

A separate author and source-only reviewer prepared the references. Before
inference, a closing ambiguity was clarified, a retrospective audit was moved
after the events it covers, and explicit negative greeting/empathy controls were
added. Original drafts and independent reviews remain preserved. Engine builders
did not see the new data; the root froze both engines before source adjudication.

The freeze contains **47 exact provisional judgments and five complete vectors**.
Case 03's consultation ordinal is excluded prospectively: the unchanged rubric
does not uniquely specify how to score a wrong key instruction withdrawn before
use with complete verified recovery. The original error and real recovery still
must be recognized. Current chooses 20; lean chooses 0. Neither choice is turned
into an exact-label win or loss after results.

All 12 executors and three paired semantic reviewers explicitly use Sol 6.1
medium without inherited chat history. Executors receive one packet and submit
once, with no labels, previous output or feedback. Reviewers see complete native
assessments and original sources, without expected labels. A score-only projection
would hide important evidence and is insufficient for this review.

## What the experiment actually exposes

The lean contract is smaller but still has avoidable representation failures:

- Its schema leaves source IDs insufficiently constrained by field. Models put
  legitimate reference citations into judgment arrays restricted to dialogue.
  Runtime validation rejects them; exact-source validation is not waived.
- A flat policy/interaction proof distinction cannot directly express every
  valid inference combining an applicable policy and a customer-reported state.
- An observable commitment is inventoried with empty grading links, rejected by
  the nonempty relevance guard. A nonmaterial promise should not require a fake
  dependency merely to complete an inventory.

The current contract also rejects useful analysis: narrow reported-state metadata
conflicts with its general-fact guard; pre-correction no-action evidence is placed
with later recovery confirmation; and a conjunctive proof uses an invalid alias.
These are not evidence that an operator event occurred differently. They are
contract failures that block otherwise useful authored assessments.

The response is to align citation representation, proof composition and generation
constraints with the evidence being expressed. Adding more audit fields or accepting
all rejected outputs would not solve that problem. No failure is hand-edited,
retagged or promoted by this report.

## Size, verification and cost

Median compact canonical wire JSON decreases from 16,415.5 to 10,563.5 bytes:
**35.65% smaller**. Median instruction-plus-schema bytes decrease from 78,208
to 10,174: **86.99% smaller**. These include rejected submissions and are not
provider token/cost measurements. The size targets pass; the reliability gate fails.

All 65 organizer input pairs preserve the full source/context. Maximum protected
input decreases from 194,078 to 105,381 bytes with the unchanged 200,000-byte guard.
No new organizer assessments were generated. The configured output cap stays
6,000; manual generation does not reproduce its enforcement or hidden reasoning use.

755 Python tests pass, with one existing Starlette warning. Ruff passes. The
historical verifier preserves 97 accepted API scores and previous frozen labels,
schemas and manual statuses. The lean candidate is isolated from production.

**API calls: 0. Incremental API cost: $0.** Ledger remains 591 rows, maximum ID
591 and $23.141316 cumulative settled cost. No top-up is needed to diagnose these
known failures. Provider schema acceptance, output limits, latency, retry behavior
and repeatability remain later gates after the free completion gate passes.

Freeze bookkeeping caveat: the review JSON retains an initial author's case-06
neutral-cue narrative saying empathy Yes. The final TestCase label and final blind
source review both say No for the subsequently added explicit complaint, before
inference. Only final TestCase labels drive exact comparisons. The older narrative
is retained as provenance; frozen bytes and labels are not rewritten.

This is a six-case targeted system comparison with different prompts and schemas,
not a single-variable ablation, expert accuracy estimate or evidence of a 95–100
product. Smaller generation is demonstrated; improved reliability is not.
