# Русская редакция основного чек-листа

Файл `checklists/freedom-reviewed-017.json` — русская редакция версии
`1-reviewed-016`, а не новый набор правил оценивания. Логический идентификатор
остаётся `freedom-chat-quality`; новая версия — `1-reviewed-017`.
Название «Чек-лист качества диалогов» отражает уже предусмотренное применение
к чатам и расшифровкам звонков.

В каждом критерии сначала дан короткий обзор, затем полные условия выбора
ответа и исключения. Английские пояснения переведены; длинные абзацы разделены
по смыслу. Исторические номера уточнений и сведения об их происхождении
перенесены сюда, чтобы не мешать чтению правил в интерфейсе.

Сохранены порядок и идентификаторы всех восьми критериев, их типы и веса,
допустимые значения ответов, доли баллов, условия неприменимости и ограничения
для звонков. Например, ответ `7` за ведение диалога по-прежнему означает
70% от веса 15, то есть 10,5 балла. Ответ `15` за консультацию означает
75% от веса 20, то есть 15 баллов. Грубые ошибки остаются отдельными отметками
с нулевым весом.

Версия 016 не изменяется. Ранее сохранённые оценки должны оставаться связаны
со своим исходным снимком чек-листа. Перевод формулировок меняет текст,
который получает модель: одинаковые результаты новых вызовов модели не
гарантируются, хотя правила и арифметика сохранены.

## Источник и статус командных уточнений

Исходная основа — документ организаторов `CQA_Chat_Quality_Checklist.pdf`,
страницы 1–3, и уточнение организаторов по звонкам от 7 ноября 2026 года.
Порог первой реакции в три минуты, теги и вложения в оценку не входят.

В версии 016 было отдельно зафиксировано: уточнения R001–R012 — рекомендации
ассистента, принятые пользователем. Последние пять проверочных оценок были
записаны по просьбе пользователя как предварительные суждения ассистента,
а не как дополнительные правила, утверждённые пользователем по итогам
разбора. Они не являются эталонной разметкой организаторов. Другие
неразрешённые предложения не приняты.

Версия 017 сохраняет также формулировки R013–R015, уже присутствующие
непосредственно в инструкциях версии 016. Их перевод не меняет исторический
статус этих уточнений и не означает нового согласования или подтверждения
организаторами.

Для R016 в версии 016 отдельно зафиксировано явное решение пользователя
от 8 ноября 2026 года: за неверное обязательное условие, исправленное до
действия клиента, при окончательно решённом запросе и отсутствии установленных
оставшихся последствий применяется уровень 15 из 20 за консультацию.
Это командное правило, а не эталонная разметка организаторов. Ограничения
этого правила — отдельный незакрытый запрос, сохраняющаяся неверная ключевая
рекомендация, установленный вред и непроверенность фактического исправления —
полностью сохранены в критерии.

## Где сохранено каждое уточнение

| Уточнение версии 016 | Раздел русской версии и сохранённый смысл |
|---|---|
| R001 | Консультация: конкретно решённый вторичный запрос при открытом основном — частичное решение, уровень 10; ошибочная ключевая рекомендация может требовать 0. Ответ бота не заменяет действие оператора. |
| R002 | Выявление потребности: сведения, собранные ботом, известны оператору; неприменимость определяется с первого существенного обращения во всём диалоге. |
| R003 | Эмпатия: уважительное признание конкретной трудности и практическая помощь могут быть достаточны без обязательного извинения. |
| R004 | Ведение диалога: один ненужный повторный вопрос — уровень 7; уровень 4 требует уточнения именно из-за непонятной формулировки или порядка объяснений. |
| R005 | Эмпатия: конкретное исправляющее действие, учитывающее поправку клиента, может быть неявным признанием трудности. |
| R006 | Консультация: ответ может быть неявным, но должен следовать из слов или подходящего следующего шага; нельзя додумывать обещания и правила. |
| R007 | Консультация: неопределённое откладывание не закрывает дополнительный вопрос; благодарность и вежливое завершение тоже не закрывают его. |
| R008 | Консультация: явно обозначенное препятствие к цели требует ответа; простая контекстная деталь не создаёт дополнительной обязательной задачи. |
| R009 | Выявление потребности: обязательная деталь нужна до зависимого действия; полезность сведений не доказывает их обязательность для более раннего шага. |
| R010 | Завершение: различаются доказанная возможность, подтверждённый обрыв до возможности и неопределённость записи. |
| R011 | Консультация: грубая ошибка не снижает балл автоматически; снижение возможно при самостоятельно подтверждённом последствии для консультации. |
| R012 | Консультация: снижение за неполноту требует конкретного незакрытого запроса или необходимого шага; отсутствие подтверждения успеха само по себе недостаточно. |
| R013 | Ведение диалога: недостаток содержания консультации сам по себе не является нарушением формы или процесса общения. |
| R014 | Эмпатия: сначала проверяются слова оператора, затем конкретный повод со стороны клиента и ответ после него. Ведение диалога: сохранены три обязательных подтверждения нарушения последовательности, границы уровней и обоснованное пересечение критериев. |
| R015 | Выявление потребности: проверка личности отделена от необходимых деталей запроса; реальные независимые нарушения могут учитываться одновременно. |
| R016 | Консультация: исправленная до действия клиента ошибочная предпосылка или ключевая инструкция оценивается уровнем 15 при всех установленных условиях и исключениях. |

В человекочитаемом тексте «Не применяется» соответствует техническому
статусу `not_applicable`. Формулировка об оставленном невыбранным ответе
сохраняет историческое правило `needs_review` с `answer: null`. В текущем
режиме оценки v3 для применимого критерия выбирается наиболее обоснованный
допустимый ответ, а неопределённость сохраняется в пояснении и предупреждении
для проверяющего. Отсутствие подтверждённой возможности завершения не
доказывает неприменимость критерия. Ранее сохранённые оценки `needs_review`
остаются неизменными. Названия полей и значения ответов `yes` / `no` в
формате данных сохранены.

Проверки в `tests/test_russian_checklist.py` подтверждают структуру,
отсутствие английского текста в отображаемых правилах и неизменность расчёта
для характерных сочетаний ответов, неприменимости и неопределённости.
Они не заменяют содержательную сверку перевода и не являются проверкой
качества новых ответов модели.
